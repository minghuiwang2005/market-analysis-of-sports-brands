# 运动品牌研究与数据实施计划

> **给执行者：** 实施时使用 `superpowers:executing-plans`；用户选择子代理方式时使用 `superpowers:subagent-driven-development`。按 `- [ ]` 跟踪真实状态。

**目标：** 建立能追溯来源、冻结版本、复算指标的 Nike 研究数据流程，并评价其质量与有限跨品牌迁移。

**架构：** 原始文件经过共享合同校验，保存成不可变快照；指标和体育证据读取快照。人工审查的修正形成新版本，保留原版本和评价结果。

**技术方案：** Python、DuckDB、JSON／CSV、派生 Parquet、pytest；文档和评价表使用中文。

**设计依据：** [项目详细规划 v2](../../overview/运动品牌市场分析项目计划-v2.md) 和 [研究总计划](2026-09-29-运动品牌研究总计划.md)。

## 全局约束

继承总计划全部约束。每条观察有来源和时间；未知日期保持空值；价格使用 `Decimal`；同一快照混币种的价格合计被拒绝；正式与示例数据分别标识。

## 优先审查

重复导入与冲突、缺失与非法价格、同款配色权重、未经证实的关系、快照被修改，分别由 R03–R06 的指定检查覆盖。

## 一、共享接口合同

以下名称在 R03 定义，后续任务只能复用，改变需同步修改计划和调用方。

| 类型 | 必填字段或约定 |
|---|---|
| `SourceRecord` | `source_id, url, source_type, market, captured_at, evidence_text, review_status`；另含公开许可状态和可选本地证据路径 |
| `ProductVariant` | `variant_id, model_id, brand, series, sport, category, age_group, program, primary_use`；另含款式编码、颜色、技术主题、技术层级、别名，以及可空的 `release_date` 与对应 `release_source_id` |
| `Observation` | `observation_id, variant_id, source_id, collection_run_id, market, channel, currency, observed_at, current_price, reference_price, reference_price_kind, status`；价格可空，日期附时区 |
| `SportsEntity` | `entity_id, entity_type, name`；类型含运动员、球队、联赛和赛事 |
| `EventRecord` | `event_id, name, event_type, occurred_on, source_id`；无法确定具体日期的事件不进入按日排序分析 |
| `RelationRecord` | `relation_id, variant_id, entity_id, relation_type, source_id, evidence_kind, review_status`；有效起止日期可空 |
| `CollectionRun` | `collection_run_id, market, channel, observed_at, entry_url, filters, expected_count, success_count, failure_count, failed_items` |
| `Dataset` | `variants, observations, sources, entities, events, relations, collection_runs, metadata`；元信息含 `data_mode=real/demo` 与分类版本 |
| `DatasetManifest` | `dataset_version, schema_version, taxonomy_version, data_mode, hashes, row_counts, created_at`；哈希包含各研究输入文件 |
| `AnalysisScope` | `dataset_version, collection_run_id, market, currency, category, sports, brands, series, age_group, programs, primary_use, price_basis, aggregation_unit` |
| `PortfolioResult` | `scope, variant_count, model_count, valid_price_count, missing_price_count, median_price, q1, q3, by_sport, by_series, by_technology, relation_coverage, method_notes`；有效和缺失价格计数按所选统计单位解释 |
| `AnalysisRecord` | `analysis_id, dataset_version, metric_version, code_revision, scope, result, source_ids, reviewer_note, created_at`；`result` 为可序列化字典，包含统计结果及所选商品的明确关系证据清单 |

`sport` 的核心编码为 `basketball`、`soccer`，`american_football` 单独保留；`category` 含 `shoe`、`jersey`。中文显示名集中映射。默认主查询为成人、鞋、实战用途、普通发售、单市场单币种、一个完整观察批次，`aggregation_unit=model`，价格默认 `current`；论文另存 `reference` 查询，只有明确参考价的商品进入该统计。

价格未知用 `None`，不填零。`reference_price_kind` 区分 `msrp`、`original`、`unknown`。`evidence_kind` 区分 `official_explicit`、`researcher_inferred`；时间共现结果不写入明确关系表。

统一错误：`ValidationError`、`DuplicateConflictError`、`MixedCurrencyError`、`MixedMarketError`、`MissingDatasetVersionError`、`SnapshotIntegrityError`、`MetricVersionMismatchError`。合法空筛选产生空结果，不产生错误。日期类型使用标准 `date`／带时区 `datetime`；内部 ID 在原始输入中固定，型号对应由经过核验的映射表提供，导入过程不做猜测式合并。

## R04：文件导入、去重与不可变研究快照

**依赖：** R03。**工时：** 16 小时。

**创建文件：** `src/sportbrand/ingest.py`、`src/sportbrand/snapshots.py`、`src/sportbrand/cli.py`、`tests/test_ingest.py`、`tests/test_snapshots.py`、`docs/research/快照与版本规则.md`。

**接口：**

- `ingest_directory(raw_dir: Path, taxonomy_path: Path) -> Dataset`
- `freeze_dataset(dataset: Dataset, root: Path) -> DatasetManifest`

- CLI：`python -m sportbrand.cli freeze --input <目录> --output <快照根目录>`；标准输出包含版本号和各表记录数。

快照结构为 `data/snapshots/<dataset_version>/records.json`、`manifest.json`；可附 `records.parquet` 作为派生缓存。规范化记录按实体类型和 ID 排序，Decimal 写为明确字符串；版本号取规范研究内容的 SHA-256，生成时间不参与版本计算。`load_dataset` 校验后将版本号放入 `dataset.metadata["dataset_version"]`；再冻结时排除这个派生字段，防止版本号自引用。

- [ ] 写 `test_duplicate_import_is_idempotent`、`test_conflicting_duplicate_is_rejected`：相同观察 ID 和内容只保留一次；同 ID 不同内容抛出 `DuplicateConflictError`。
- [ ] 写 `test_stable_version_for_same_records`、`test_changed_input_creates_new_version`、`test_tampered_snapshot_is_rejected`：顺序变化不改版本，内容变化新建版本，文件被修改抛出 `SnapshotIntegrityError`。

- [ ] 实现导入、规范化、来源外键检查、冲突处理、快照写入与读取校验；读取先查哈希再使用数据。

## R05：产品组合和价格指标

**依赖：** R04。**工时：** 14 小时。

**创建文件：** `src/sportbrand/metrics.py`、`tests/test_metrics.py`、`tests/fixtures/metric_cases.json`、`docs/research/指标口径.md`。

**接口：**

- `select_products(dataset: Dataset, scope: AnalysisScope) -> list[ProductVariant]`
- `compute_portfolio(dataset: Dataset, scope: AnalysisScope) -> PortfolioResult`

`metrics.py` 提供 `METRIC_VERSION = "1.0"`，口径变更时更新该值。`by_technology` 使用商品已有的人工核验主题，多标签可交叉；注明分母和多标签占比可能超过 100%，不推断性能。`relation_coverage` 返回明确关系数、选中款式配色分母与比例，保持它与价格统计单位区别可见。

价格口径：先筛选一个观察批次和同市场币种；型号等权时，先求该型号有效配色价格的中位数，再统计型号间分布。四分位数使用线性插值，算法和指标版本写入方法说明；显示金额保留两位小数，计算过程不以页面舍入结果为输入。

- [ ] 写一个合成边界用例：型号 A 有三个配色价格 100、110、120；型号 B 价格 200。断言型号等权中位数为 `Decimal("155")`，配色等权中位数为 `Decimal("115")`；明确用例是测试数据。
- [ ] 写 `test_mixed_currency_is_rejected`、`test_mixed_market_is_rejected`、`test_missing_reference_price_is_excluded`、`test_empty_scope_returns_empty_result`；断言错误类型、缺失数、空统计值为 `None`。
- [ ] 写 `test_relation_coverage_uses_explicit_evidence`：有官方明确证据的比例与其他推断分开；分母包括选中范围全部款式配色，分子只计不同 `variant_id`，空分母结果为 `None`。
- [ ] 运行 `python -m pytest tests/test_metrics.py -q` 验证尚未实现行为。
- [ ] 实现筛选、型号／配色双口径、分组、中位数、四分位数、缺失与证据覆盖，使用 DuckDB 或 Python 的明确可核算算法。
- [ ] 对真实冻结快照输出数量与价格原型表，并核对随机选取记录。
- [ ] 重跑检查并保存指标定义和代码版本。

**验收：** 同款多配色不会改变型号权重；混市场／币种输入不能被当作一个价格分布；图表需要的样本数与缺失数均可取得。
