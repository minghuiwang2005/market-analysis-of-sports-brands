# Nike 研究论文与申请作品集实施计划

> **给执行者：** 使用 `superpowers:executing-plans` 按任务推进；用户选择子代理方式时使用 `superpowers:subagent-driven-development`。中文步骤采用 `- [ ]` 跟踪。研究结论须由研究者核对。

**目标：** 用真实分析与评价支持一篇完整综合论文，并将研究过程整理为申请摘要、作品集和演示。

**架构：** 案例图表与结论证据表来自固定研究快照和已保存分析；论文解释方法和局限；作品集使用论文已验证的数字和实际完成状态。

**技术方案：** 中文 Markdown 写作、文献管理、Python 与 Matplotlib 导出研究图表、HTML／Markdown 展示材料；后续需要 Word 或 LaTeX 时另行排版。

**设计依据：** v2 项目计划、研究总计划及研究／平台子计划。

## 全局约束

继承总计划。先完成一篇综合论文；研究问题为 RQ1–RQ3；论文标题、贡献与新颖性在文献检查后收敛。只有真实数据和已完成评价可写为结果；目录数量、搜索关注和评论均不等同销量。

## 优先审查

优先检查统计粒度、样本范围外推、无证据关系、图表版本不一致、论文和发布状态被夸大。分别由 A01、A03、A05 验收。

---

## 一、论文主题与章节分工

暂定中文题目：《面向运动品牌产品与体育生态分析的可复现工具：Nike 篮球与足球案例研究》。

| 章节 | 要回答的问题 | 主要输入 |
|---|---|---|
| 摘要和引言 | 问题是什么，研究做了什么？ | R01、最终真实结果 |
| 相关研究 | 现有研究与工具有哪些不足？ | 文献矩阵和差异记录 |
| 研究设计 | 为什么选这些市场、系列和指标？ | R01–R03 |
| 数据模型与平台 | 如何统一商品、来源、观察和体育关系？ | R03–R06、P01–P06 |
| 工具与数据评价 | 分类、复现与迁移表现如何？ | R07、R08、P06 |
| Nike 案例结果 | 篮球和足球的结构与价格有什么差异？ | A01 |
| 讨论、局限和结论 | 可以解释什么，仍有哪些替代解释？ | 全部证据与未解决问题 |

首期关注产品供给、价格结构和体育关联。行业与经营资料用于背景；目标消费者描述只有产品适用人群时，应称品牌标注人群，不推断真实购买者画像。

## A01：案例分析、稳健性与结论证据

**依赖：** R07、R08、P06；缺少迁移时记录其状态并缩减 RQ1 主张。**工时：** 12 小时。

**创建文件：** `paper/案例分析.md`、`paper/结论证据表.csv`、`paper/图表清单.csv`、`paper/figures/`、`scripts/export_paper_figures.py`。

**输入：** 已冻结快照、五个分析记录、质量与迁移评价。**输出：** 两个场景案例、论文图表、支持和不支持的主张清单。

- [ ] 固定论文主数据版本及统计口径；记录实际市场、时间、系列、样本和缺失。
- [ ] 导出产品组合、型号价格分布、系列分层、明确关系覆盖和事件证据时间线。不存在时间面板时只导出静态证据案例。
- [ ] 对比型号等权／配色等权、当前价／明确参考价、排除／包含特殊类型；保存会改变结论的情况。
- [ ] 完成篮球鞋对足球鞋的分层比较；球衣另建独立表，不混入鞋价。
- [ ] 每条主张登记证据类型、分析 ID、版本、数值、来源、替代解释和外推范围。
- [ ] 技术描述只解释为公开卖点；联名价差和体育事件共现说明可能的组成和时间因素。
- [ ] 核对导出图表与 P06 回放结果一致，保存分析与图表版本。

**验收：** 每张图有分析 ID 和版本；每条结论有证据或明确标记为讨论假设；没有用缺失历史补画趋势。

## A02：形成完整论文

**依赖：** A01；方法和文献在前期持续积累。**工时：** 22 小时。

**创建文件：** `paper/论文初稿.md`、`paper/参考文献.bib`、`paper/方法附录.md`、`paper/研究贡献说明.md`。

**输入：** 文献、研究设计、平台、评价和案例。**输出：** 可阅读全文的一篇中文初稿。

- [ ] 检查高度相关文献与本项目的具体区别，收敛贡献，不以“首个”作为未经证明的定位。
- [ ] 完成研究设计与方法：采样、三类时间数据、分析单位、缺失、指标和评价。
- [ ] 完成模型与平台章节，解释用户任务、来源链和复现流程，而不是逐页罗列按钮。
- [ ] 写评价章节，报告初次错误、修正、人工核验限制与迁移失败；无用户实验时不宣称效率提升。
- [ ] 写案例结果和讨论，将观察事实、统计关系、策略解释与因果限制分开。
- [ ] 完成引言、摘要与结论，使 RQ1–RQ3 均有回答或无法回答的原因。
- [ ] 建立参考文献和方法附录，核对关键引用与原文一致。
- [ ] 保存完整初稿版本。

**验收：** 各章节完整，不存在留空结果；贡献有评价支持，负面结果与限制可见。篇幅根据用途调整，本计划不硬性套用期刊字数。

## A03：论文证据、图表与引用审查

**依赖：** A02。**工时：** 10 小时。

**创建文件：** `paper/审查记录.md`、`paper/论文修订稿.md`、`paper/修订说明.md`。

**输入：** 初稿、图表和分析记录。**输出：** 审查问题、修订稿和修订依据。

- [ ] 按结论证据表逐条核对正文数字、分母、单位、数据版本和引用。
- [ ] 检查“市场份额、导致、销量、用户偏好、通用”等词是否超出证据；修正或提供额外支持。
- [ ] 检查每张图的标题、轴、币种、时间、统计单位、来源和可读性；论文图表使用正式导出文件。
- [ ] 重跑五个固定问题核对结果，再检查稳健性中结论不一致的情况是否写入讨论。
- [ ] 如有导师或同学反馈机会，提供具体问题清单并记录真实意见；无人参与则标记为作者自审。
- [ ] 形成修订稿与逐条修订说明，保存版本。

**验收：** 关键数字可复核，引用能支持对应叙述；稿件类型、作者贡献和评价方式准确。

## A04：作品集、一页摘要与演示

**依赖：** A03。**工时：** 10 小时。

**创建文件：** `README.md`、`portfolio/项目展示.md`、`portfolio/一页摘要.md`、`portfolio/演示脚本.md`、`portfolio/个人贡献与工具使用.md`。

**输入：** 实际平台、论文与决策记录。**输出：** 申请者可讲清楚的项目故事和真实演示。

- [ ] 整理研究问题、资料限制、设计决策、主结果、评价与下一步的完整故事。
- [ ] 写一页摘要，包含实际样本、方法、核心图、贡献、限制、论文状态和成果入口。
- [ ] 编写 3–5 分钟演示：问题 → 数据与模型 → 一个完整分析任务 → 结果与评价 → 个人贡献。
- [ ] 从实际平台截取图像或演示片段；示例数据画面明确说明，优先展示真实冻结案例。
- [ ] 写个人贡献和 AI／工具使用范围，保留能独立解释的数据定义、方法和关键决策。
- [ ] README 提供经过实施验证的安装、运行和复现步骤；规划中的未来命令不能直接写成已可用功能。
- [ ] 练习解释型号与配色、来源限制、跨品牌迁移和不能得出的因果结论；保存材料版本。

**验收：** 演示与论文数字一致，个人贡献具体；“已实现、计划中、草稿、在投、已发表”按真实状态表述。

## A05：研究包与最终交付

**依赖：** A04。**工时：** 6 小时。

**创建文件：** `docs/research/最终交付清单.md`、`docs/research/公开与私有资料清单.csv`、`releases/研究包清单.json`。

**输入：** 全部真实交付。**输出：** 可演示、可复核、状态准确的项目提交版本。

- [ ] 列出平台、论文、数据字典、来源、五个分析记录、核验与迁移报告、摘要和演示。
- [ ] 记录公开和私有资料范围；不适合再发布的原始内容在清单中给出复现替代办法。
- [ ] 保存研究包中文件的版本与哈希，并核对文件可打开、链接有效、说明完整。
- [ ] 在干净环境或独立目录按 README 完成一次真实流程；必要检查选择与该交付相关的范围，避免无理由反复运行全部任务。
- [ ] 对照总计划 M4 核实交付状态，未完成事项写明，不以完整界面替代论文或研究评价。
- [ ] 整理下一步研究建议；公开部署、投稿和发布采用各自实际行动状态。
- [ ] 保存最终提交版本。

**验收：** 有一份可以复核的完整研究包；申请材料只使用真实完成成果。正式投稿与录取结果不属于平台功能验收。

## 二、不同申请方向的调整

| 方向 | 优先展示 | 调整方式 |
|---|---|---|
| 市场营销／商业分析 | 产品定位、价格结构、体育关联及解释 | 精简界面，增加文献和品类内比较 |
| 数据科学／信息系统 | 合同、质量、快照、复现和迁移 | 展示错误修正与评价，复杂模型按问题需要选择 |
| HCI／产品设计 | 研究者任务、可用性和证据理解 | 增加小规模用户任务方案，缩减其他研究范围 |
| 体育管理 | 联赛、球队、球员关系与产品案例 | 丰富官方事件资料，强调关系有效期和研究边界 |

专业方向变化时先修订 R01，不同时扩张数据源、市场和平台功能。

## 三、停止或缩减条件

申请时间不足时，优先完成单快照案例、基础平台、完整论文草稿和演示。无法获得真实销售、历史面板或独立核验者时，缩减相应主张；如实报告限制仍能形成完整研究。
