# NBA 双轨历史时间轴设计

## 状态

- 阶段：已确认并实现
- 日期：2026-10-30
- 相关路由：`/sports/nba`
- 设计依据：用户已确认把时间轴改为从现在向下追溯至 1946 年，以中央轴线分隔 NBA 事件与球星签约时间；事件与来源数据遵循项目 Neon 存储约定。

## 目标

将 NBA 页面现有的单列历史列表调整为自上而下、年份倒序的双轨时间轴。中央轴线左侧展示 NBA 重大事件及年份；右侧展示球星与 Nike/Jordan 的签约事件。NBA 大事件继续按类别使用颜色，签约事件使用另一种固定颜色。

NBA 事件与签约事件都由 Neon 提供，不在 React 页面中硬编码。每条事件附有来源信息与核验状态，以支持后续研究、校正和复核。

## 设计方案与范围

采用 Neon 驱动的双轨时间轴，而不是只通过 CSS 重排当前组件中的静态事件。项目约定数据源保存在 Neon；当前 NBA 事件数组直接定义在 `src/app/sports/nba/page.tsx`，因此只做展示改造会继续让页面内容绕开数据库。

### 时间轴布局

- **桌面端**：时间轴区域为三列结构：左侧 NBA 事件卡、中间轴线、右侧球星签约卡。中轴位于时间轴容器水平中心。
- 每个年份为一个纵向节点组。同一年出现 NBA 事件和签约事件时，卡片分别放在轴线两侧并对齐；只有一侧有事件时，另一侧留空。
- 年份组从最近年份向过去排序，最早显示到 1946 年。只渲染有事件的年份，不为无事件年份生成空白节点；纵向间距表示事件顺序，不表示严格按年差缩放的时间距离。
- 多条同年事件按日期精度（年月日、年月、年份）及数据中的稳定排序字段排列。日期不完整时不制造精确日期。
- NBA 事件保留现有类别及其图例颜色；签约事件使用独立的品牌关系颜色，并在图例中标为“球星签约”。卡片呈现标题、年份/日期、简述和来源链接。
- **窄屏**：中央线移动到内容列左侧，事件卡改为单列；每条仍标识 NBA 大事件或球星签约，顺序仍由新到旧。这样保留时间方向，同时避免左右卡片挤压可读宽度。

### 事件范围

- 将现有 NBA 历史事件迁入 Neon，保留现有从 1946 年至最近展示年份的精选节点、描述、类别和来源。
- 增加能从可靠公开资料核实的 Nike/Jordan 球星签约事件。签约主体为球星，合作对象为 Nike 或 Jordan Brand；若资料未公布确切签约日，记录有来源支持的年份/月精度。
- 不把首代签名鞋发售时间、首次穿着某品牌球鞋、或某个鞋款仍在销售，误写为球星签约时间。若签约时间没有可靠公开记录，则不生成签约事件；可在未来另行引入“签名鞋系列首发”事件类型，并和签约事件明确区分。
- 签约事件首批优先覆盖本项目球星目录关注的 NBA 球员；不因“至少 15 位球星”的档案目标，推断所有人都有已知公开签约日期。

## 数据模型提案

数据仍使用现有 Drizzle/PostgreSQL 技术栈，以版本化 migration 创建表和种子数据。建议使用专用事件表与事件来源表，而不是复用仅关联商品的 `source_records`。

### `sports_timeline_events`

- `id`：UUID 主键
- `sport`：首期为 `nba`，后续可扩展其他运动
- `event_type`：`league_milestone` 或 `athlete_signing`
- `category`：NBA 大事件类别；签约事件使用 `athlete_signing`
- `occurred_year`：必填年份
- `occurred_month`、`occurred_day`：可空；只记录来源确实支持的精度
- `date_precision`：`year`、`month` 或 `day`，并校验与年月日列一致
- `athlete_name_zh`、`athlete_name_en`：签约事件使用；NBA 大事件为空
- `organization`：签约对象，例如 Nike 或 Jordan Brand；NBA 大事件可空
- `title`、`description`：面向页面的标题和中文说明
- `sort_order`：同年、同粒度事件的稳定顺序
- `published`：控制是否出现在公开页面
- `created_at`、`updated_at`

### `sports_timeline_event_sources`

- `id`：UUID 主键
- `event_id`：必填外键至时间轴事件，删除策略为 restrict
- `url`、`publisher`、`source_title`、`published_at`：来源定位信息
- `claim_scope`：例如 `league_event` 或 `athlete_signing`
- `evidence_note`：来源具体支持的事实摘要
- `checked_at`、`verification_status`：核验时间与 `verified` / `needs_review` 状态
- `created_at`

事件查询索引覆盖 `sport`、`published`、`occurred_year` 与 `sort_order`；来源查询索引覆盖 `event_id`、`verification_status`。迁移种子使用稳定事件键与 upsert/冲突忽略，以便重复部署不重复插入。

## 数据流与组件边界

1. 由 `getDatabase()` 提供 Neon/Drizzle 连接。
2. 新增 server-only 时间轴查询函数，按运动类型读取已发布事件及来源，排序后按 `occurred_year` 聚合成页面所需年份节点 DTO。
3. `src/app/sports/nba/page.tsx` 保留页面介绍区和 NBA 信息区；将静态 `events` 数组移除，改为调用查询函数，并把结果传给双轨展示组件。
4. 双轨组件按 `event_type` 分配左右栏；事件颜色来自 NBA 类别或签约事件类型，不由卡片文案推断。
5. 迁移包含现有精选 NBA 事件的逐条搬迁，并新增通过证据核验的球星签约事件；来源记录和事实事件同一事务插入。

本期不开放公众或管理员 CRUD；纠错通过后续有权限的管理流程或新的受控数据迁移处理。

## 查询、日期和来源规则

- 排序先按 `occurred_year DESC`，再按可确认的月、日从晚到早，最后使用 `sort_order` 确定稳定顺序。查询 DTO 同时保留 `date_precision`，展示时只显示已有精度。
- 同一事件可关联多个来源；至少一个经过核验且支持目标事实的来源后才可设为 `published = true`。
- NBA 联盟事件来源优先采用 NBA / NBA G League 等官方材料；球星签约来源优先采用 Nike/Jordan 官方资料、球员或经纪方公开声明及可信的一手同期新闻稿。来源必须支持“签约”这一主张本身。
- `first_seen_at`、首代签名鞋发布日期、品牌照片、球员穿着照片均不能单独证明签约发生时间。
- 来源失效后保留原记录并改为待复核，不删除历史证据或把未核实日期改得更精确。

## 错误处理与降级

- Neon 未配置或查询失败时，沿用平台数据库错误边界显示明确中文提示；不得静默回退到静态数组。
- 查询成功但没有已发布事件时显示空状态，不显示伪造时间轴。
- 失效来源仍保留可见的来源状态；页面只显示已发布的核验内容，待复核条目不进入公开时间轴。

## 无障碍与响应式

- 使用有序列表/分组语义表达时间先后；屏幕阅读顺序为年份、左侧 NBA 事件、右侧签约事件。
- 类别文字与颜色同时呈现，颜色不是唯一信息通道；节点和文字需达到足够对比度。
- 窄屏时中轴移到左侧，卡片按年份顺序垂直排列；链接仍可通过键盘聚焦。

## 本期不做

- NBA 重大事件档案的搜索、筛选、编辑后台和批量导入。
- 签名鞋首发/发售时间、品牌代言事件、球员转会、奖项等其他事件类别。
- 以年份估算精确签约日，或对签约年份进行统计推断。
- 足球、网球、田径时间轴页面。
