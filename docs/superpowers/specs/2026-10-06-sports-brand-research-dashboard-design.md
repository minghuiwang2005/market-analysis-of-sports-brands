# 运动品牌市场研究工作台设计规格

## 1. 项目目标

构建一个中文研究型网站，以 Nike 为首个案例，帮助研究者完成产品目录筛选、价格与产品组合分析、体育生态证据检查、研究查询保存和报告导出。首版服务运动品牌市场研究与研究生申请作品集展示，核心是让分析范围、数据版本、统计单位和证据来源能够被读者理解与复核。

首版覆盖 Nike 成人篮球与足球表现类鞋款研究。页面架构应允许后续扩展 Adidas、Puma 等品牌，但本阶段不要求接入这些品牌的数据。

## 2. 用户与首版任务

目标用户是需要开展运动品牌市场研究的学生或研究者。首版应支持以下主任务：

1. 进入研究工作区，选择篮球或足球主题及一个研究问题。
2. 查看当前快照的市场范围、批次、样本量、时间覆盖和数据质量。
3. 按品牌、运动、系列、型号、价格及人群等字段筛选商品，并查看单品来源。
4. 比较系列结构与价格分布，切换型号等权或配色等权统计口径。
5. 查看球员、球队、联赛和赛事相关证据，并区分直接证据与时间共现。
6. 保存研究范围并导出含口径、版本、样本量和来源说明的报告。

## 3. 首版范围

### 包含

- 六个研究页面：研究工作区、数据概览、产品目录、组合与价格、体育生态、报告导出。
- 以本地不可变快照作为分析输入。
- 展示数据来源、采集时间、核验状态、市场、批次、币种、版本和统计单位。
- 支持空筛选、价格缺失、来源缺失和无体育关系证据等状态的清晰展示。
- 提供明确标注的示例数据，使空仓库也能启动和演示。
- 报告以 Markdown 和 HTML 导出。

### 暂不包含

- 用户账户、云端协作、自动采集爬虫、付费服务。
- 未经来源支持的销量、市场份额或合作关系推断。
- NBA 与篮球的等同判断，或赛事同期出现到因果关系的推断。
- 第二品牌正式数据接入、搜索趋势和复杂关系图。
- 独立 React 前端或线上生产部署。

## 4. 技术架构

- **界面与页面路由：** Python、Streamlit，以 `st.Page` 与 `st.navigation` 组织多页面界面。
- **研究计算：** Python 领域层；页面只调用共享查询和指标接口，不复制统计逻辑。
- **分析与快照：** DuckDB 查询 Parquet/CSV 数据；快照只读且按版本组织。
- **可视化：** Altair；所有统计图展示单位、样本数量、筛选范围和必要注释。
- **报告：** 研究记录序列化为 JSON，支持 Markdown 与 HTML 预览、下载。
- **检查：** pytest 验证分析、快照、报告及页面关键状态；Streamlit 页面可用 AppTest 检查。

初始目录按既有数据计划提供的接口逐步建设：`app.py`、`ui/`、`src/sportbrand/`、`tests/`、`data/snapshots/`、`data/projects/`、`data/analyses/`。首个交付先实现可启动的页面框架和示例数据；真实快照加载通过数据计划中的接口接入，不在 UI 层另造一套字段或指标。

## 5. 页面结构与职责

| 页面 | 用户看到的内容 | 核心操作 |
|---|---|---|
| 研究工作区 | 篮球/足球研究入口、最近项目、研究问题、当前快照摘要 | 创建或恢复研究项目 |
| 数据概览 | 数据覆盖、商品与来源数量、缺失项、批次状态、时间范围 | 切换快照、查看数据质量 |
| 产品目录 | 筛选器、商品表、型号/配色计数、来源详情 | 筛选目录、打开商品详情 |
| 组合与价格 | 系列构成、价格分布、分组统计表与分析说明 | 切换运动、系列、币种和统计单位 |
| 体育生态 | 球员/球队/联赛关系、来源、有效日期、赛事时间线 | 按证据类型检查关系 |
| 报告导出 | 报告预览、分析范围、方法、样本、版本、来源 | 保存分析记录、下载 Markdown/HTML |

全局范围栏展示当前品牌、运动、市场、快照和批次；页面的分析范围须保持一致。商品详情采用目录页中的侧栏或展开视图，不增加顶层导航项。

## 6. 数据展示与研究口径

- 每次分析绑定明确的快照版本和批次。恢复旧项目时保留其原版本；版本不可用时要求用户明确选择替代版本。
- 型号数与配色数是不同计数口径，界面必须清楚标记；价格摘要同时显示所用统计单位。
- 缺失价格不得转成零；合法空结果不得显示为零价格。
- 不得混合不同币种计算价格。没有单币种筛选时说明无法比较。
- “目录商品占比”只能描述观察到的目录结构，不得称为销量或市场份额。
- 来源信息缺失应标记为缺失；来源不可用或批次失败不能表示成商品下架。
- 体育关系分为来源明确支持的直接关系、待核验关系、仅时间共现。时间共现不得描述成赞助或合作。
- 示例数据在页面、图表和导出报告中均应明显显示“示例数据”。

## 7. 视觉与交互规范

采用“运动研究报告 × 数据工作台”视觉方向：浅灰白页面底色、深色正文、蓝色交互强调色，少量亮绿色用于重点状态或数字标记。以清晰表格和可读图表为主，避免仿造 Nike 标志或将站点做成品牌营销首页。

- 桌面端使用左侧主导航、顶部全局研究范围、主体内容区；窄屏将筛选器改为可折叠区域并纵向排列内容。
- 正文默认不小于 16px，文字、状态色和图表图例保持可辨识；焦点、悬停和禁用状态需明确。
- 颜色不能作为唯一状态提示；状态同时使用文字或图标。
- 图表提供清楚的标题、单位、图例、工具提示与无数据状态。
- 页面文案使用研究语言，代码和调试信息不进入主要阅读路径。

## 8. 错误与空状态

- 找不到快照、快照版本损坏或必需表缺失：显示具体文件/版本问题，并停止依赖该快照的分析。
- 当前筛选没有商品：显示“当前筛选下暂无商品”，保留筛选值供用户修改。
- 商品或来源字段缺失：以缺失/待核验状态显示，不补造内容。
- 混合币种、无有效价格或无关系证据：说明不可计算或暂无证据，不生成虚构数值。
- 报告无法导出：保留当前筛选和分析记录，展示可读错误。

## 9. 首版验收标准

1. 安装项目依赖后可以通过 `streamlit run app.py` 启动并访问六个页面。
2. 默认示例数据在每个相关页面及报告中有明确标识。
3. 页面间的分析范围、版本、币种与统计单位一致且可见。
4. 产品筛选能区分有效结果和合法空结果；来源信息可追溯。
5. 型号/配色口径、缺失价格、混合币种及无证据关系均按本规格处理。
6. 报告包含研究范围、方法/统计单位、数据和指标版本、样本量及来源说明。
7. 自动检查覆盖关键分析行为和页面错误/空状态；实际界面需人工检查中文可读性与图表标签。

## 10. 实施边界

本规格描述第一阶段的可运行研究工作台。实施顺序从应用骨架与演示快照开始，再接入共享数据接口，随后依次完成目录、质量概览、价格比较、研究工作区、体育生态和报告导出。只有底层数据和指标合同可用后，页面才显示对应的真实研究结果。
